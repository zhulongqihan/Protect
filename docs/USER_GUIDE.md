# 用户使用手册

这份手册面向不熟悉电脑健康指标的 Windows 用户。建议第一次运行前保存正在编辑的文件，关闭不需要的程序，并确保重要资料已经有独立备份。

## 你会看到什么

页面顶部先给出一个总体判断：

- **正常**：当前可见的关键检查通过。
- **需要关注**：空间未达到健康线、实时防护未开启、没有足够权限或某项检查结果不完整。
- **立即处理**：某个磁盘可用率低于 10%，或者出现需要优先处理的严重问题。
- **未核验**：系统没有提供足够证据，不能把它当成正常。

空间健康线默认是 20% 可用。这个数值用于提醒系统更新、临时文件和应用运行需要余量，不代表每个人都必须删除到某个固定大小。

“保护”区域会分别显示防火墙、杀毒策略、系统更新、备份与还原点和物理磁盘。按需杀毒不是常驻实时防护，页面会明确显示这一点；工具不会替你开启 360 或 Defender。

## 第一次运行

在仓库目录打开 PowerShell：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Setup.ps1
.\Start-Maintenance.cmd
```

默认是全盘只读扫描。它会读取固定磁盘上的文件元信息，按规则生成清理候选项；不会把路径或报告发送到网络。扫描较慢时可以先运行：

```powershell
.\Start-Maintenance.cmd -Fast
```

快速模式会先读取安全清理根目录和各磁盘根目录文件，适合先判断工具能否运行；之后建议再做一次默认全盘扫描。

## 怎么看清理清单

每行都会显示：

- 完整路径：确认它属于哪个程序或目录；
- 文件大小：估算释放空间；
- 类别：缓存、临时文件、日志、构建产物或大文件待审；
- 风险：低、中或高；
- 原因和可恢复性：解释为什么进入清单。

安全缓存目录可能作为一行目录候选出现，原因旁边会显示目录内文件数和总大小；这样可以逐项审阅整个可重建目录，而不会把同一缓存拆成成千上万行。

个人资料目录以及常见的照片、视频、音乐、办公文档、PDF 和压缩包会被保护，不进入清理审批清单。大文件也不会因为“很大”就自动删除。

先用筛选器查看一个类别，再逐项勾选。页面的“勾选当前筛选结果”会勾选筛选器当前返回的全部项目，适合批量审批同一类别；如果不确定，请继续逐项勾选。清单很多时使用路径搜索，确认筛选条件后再导出。

## 导出和执行审批

点击“导出审批文件”后，浏览器会下载一个 JSON 文件。这个文件只包含清单批次编号和你选择的候选 ID，不复制完整路径到公开仓库。

把审批文件路径传给：

```powershell
.\Apply-Approved-Cleanup.cmd -ApprovalFile "C:\Users\<user>\Downloads\approval-<run-id>.json"
```

默认送入回收站，适合第一次使用。脚本执行前会检查：

1. 审批批次是否仍是当前清单；
2. 每个 ID 是否确实存在于当前清单；
3. 文件是否仍在固定本地磁盘；
4. 文件大小和修改时间是否与扫描时一致；
5. 是否属于系统保护路径或个人资料。

任何一个项目预检失败，整批不会开始处理。高风险大文件还需要：

```powershell
.\Apply-Approved-Cleanup.cmd -ApprovalFile "C:\path\to\approval.json" -AllowHighRisk
```

如果只想先验证审批文件和预检流程，可以加 `-WhatIf`；它会生成结果记录，但不会处理文件：

```powershell
.\Apply-Approved-Cleanup.cmd -ApprovalFile "C:\path\to\approval.json" -WhatIf
```

永久删除需要同时明确指定：

```powershell
.\Apply-Approved-Cleanup.cmd -ApprovalFile "C:\path\to\approval.json" -Permanent
```

永久删除前请确认已经不需要这些文件。个人资料保护仍然有效。

## 清理后怎么看电脑是否健康

脚本会生成新报告并重新打开页面。重点查看：

- 目标磁盘可用率是否接近或超过 20%；
- 清单是否明显减少；
- 物理磁盘是否仍显示健康；
- Windows Update 服务是否正常；
- 防火墙是否全部开启；
- 备份和还原点是否“未核验”或“需要关注”；
- 常驻杀毒策略是否按你的选择保持按需防护。

历史区域最多保留 90 次本地报告。它只在本机 `runtime/` 中保留，不会随源码提交。

## 常见问题

### 页面显示演示数据

说明 `runtime/data/latest-status.js` 尚不存在或无效。先运行 `Start-Maintenance.cmd`，然后点击“刷新报告”。

### 清单是空的

空清单可能代表扫描根目录没有符合规则的候选项，也可能是权限不足。以管理员身份重新运行，并检查报告中的扫描结果。工具不会为了填满清单而把普通个人文件列入候选。

### 报告显示未核验

用管理员 PowerShell 重新运行即可补充部分系统信息。权限不足时工具保留“未核验”，不把缺失证据当作通过。

### 审批文件被拒绝

通常是重新扫描后批次发生变化，或文件在审批后被修改。重新打开页面，导出最新审批文件。不要手工编辑 ID 或路径。

### 回收站空间没有立即增加

送入回收站后，空间可能仍被回收站占用。确认文件无误后，由你在 Windows 回收站中决定是否清空。
